About The Alkane

The Alkane is a free tool that converts the structure of an organic molecule into its IUPAC systematic name. Draw the molecule as atoms and bonds in the browser, or send the same structure to its public API, and it returns the exact name — or explains why the structure is outside what it can name.

What is The Alkane?

The Alkane is a free, open-source IUPAC name generator: it takes an organic structure — drawn in a browser editor or submitted as a JSON list of atoms and bonds — and returns the systematic name that IUPAC nomenclature assigns to it, or refuses if the structure falls outside its supported scope. The naming engine is a deterministic rules engine, not a statistical or machine-learning model, so a given structure always produces the same result and the tool never emits a name it cannot justify from the rules.

How does it work?

A molecule is represented as a graph, not a picture: each atom is a node with an element symbol, and each bond is an edge with an order of 1, 2 or 3. The browser editor lets you build this graph by clicking atoms and bonds — there is no diagramming library underneath, the SVG on screen is only a rendering of the graph — and on every edit the graph is serialised to JSON and sent to the naming engine, which walks it, works out the parent chain or ring, numbers it, orders the substituents, and returns the name. Because the engine applies fixed IUPAC rules rather than pattern-matching against known molecules or predicting from training data, its output is reproducible and it never hallucinates a plausible-looking name for a structure it does not recognise.

Hydrogens can be left out of the graph; the engine fills them in from each atom's valency deficit. Aromatic rings must be drawn Kekulé-style, with bond orders alternating 1,2,1,2,1,2 around the ring — a six-membered ring drawn with all single bonds is named as cyclohexane, not benzene, because that is the structure that was actually submitted.

What can it name?

The engine covers organic nomenclature up to first-year undergraduate level, built from the elements C, H, O, N, F, Cl, Br, I and S, with main chains of one to ten carbons.

Category Covered
Hydrocarbons Straight and branched alkanes, alkenes and alkynes, correctly chain-selected and numbered
Suffix-capable groups Carboxylic acid, acyl chloride, amide, nitrile, aldehyde, ketone, alcohol, thiol, amine, imine — named as a suffix when the principal group, a prefix otherwise
Prefix-only groups Fluoro, chloro, bromo, iodo, nitro, with multiplying prefixes di– to nona–
Rings cyclopropane to cyclodecane with substituents, and benzene (drawn Kekulé-style)
Benzene derivatives Retained parent names — phenol, phenylamine, benzoic acid, benzoyl chloride, benzamide, benzonitrile, benzaldehyde — plus aryl ethers such as methoxybenzene
Bridged linkages Esters, ethers, amines, amides and anhydrides, e.g. methyl ethanoate, methoxyethane, N-methylethanamide, ethanoic anhydride

The editor offers three formula styles — displayed, structural and skeletal — plus a functional-group menu (carbonyl, carboxylic acid, acyl chloride, amide, nitrile, nitro, methoxy), undo/redo and a delete mode, so the same structure can be built and checked in whichever notation a syllabus uses.

What will it refuse to name, and why?

It names a molecule exactly or rejects it outright — it never guesses. An unsupported structure returns an HTTP 422 error with an explanation instead of an approximate or best-guess name. This matters most for anyone checking their own working: a wrong-looking name would be misleading, but a rejection tells you plainly that the structure is outside scope.

Out of scope Examples
Fused, bridged or spiro ring systems naphthalene, decalin, spiro compounds
Heterocycles and rings with a ring heteroatom THF, epoxides, pyrrolidine, lactones
Stereochemistry E/Z and R/S descriptors — the model carries no 3D information
Charged species, isotopes, radicals, organometallics not representable in the atom-and-bond input model
Chains longer than ten carbons no root name exists beyond dec-
Two heteroatoms bonded to each other peroxides, hydrazines, nitroso, nitrite and nitrate esters
More than one bridging heteroatom dimethoxymethane, acetals
Branches on branches, or two groups on one branch tip not modelled by the substituent grammar
Other unmodelled classes sulfonic acids, ureas, carbamates, azo/diazo compounds, multiplicative di-suffix naming on rings

Who is it for?

Anyone learning or teaching organic nomenclature. Students use it to check their own working while practising naming: draw the structure you are trying to name, compare it with the answer you worked out by hand. Teachers use it to generate practice molecules and verify answer keys quickly. Developers use the free public API to add structure-to-name conversion to their own tools without writing a naming engine from scratch.

Is there an API?

Yes. The naming engine is exposed as a free public HTTP API at POST https://api.thealkane.com/api/name, with a health check at GET https://api.thealkane.com/api/health and interactive documentation at api.thealkane.com/swagger. The request body is a JSON list of atoms, each with an element symbol and a list of bonds to other atom indices; hydrogens can be omitted and are filled in automatically. Ethane, for example: 

POST https://api.thealkane.com/api/name

{
  "atoms": [
    { "element": "C", "bonds": [{ "to": 1, "order": 1 }] },
    { "element": "C", "bonds": [{ "to": 0, "order": 1 }] }
  ]
}

returns:

{ "names": ["ethane"] }

A structure the engine cannot name — a fused ring, say, or a charged species — returns HTTP 422 with an error message rather than a fabricated name.

Is it free, and is it open source?

Yes to both. The Alkane needs no account, no payment and no install. The public API is free to call; a per-IP fair-use rate limit may apply, which returns HTTP 429 if you exceed it, so batch jobs should back off rather than retry hard. The naming engine (C# / .NET) is open source at github.com/aarianmm/Organic-Namer-Engine. The web front end is React and TypeScript with no diagramming library — the molecule is held as a graph and rendered as SVG directly.

How accurate is it?

As accurate as its rules are, by construction, because it is a deterministic rules engine rather than a statistical model: the same structure always produces the same name, and the name is derived by applying IUPAC selection rules (longest chain, most suffix groups, lowest locants, in that order) rather than guessed from similar-looking examples. Where the rules genuinely leave two chain choices equally valid, the API returns both names rather than picking one arbitrarily. If you find a structure that is named incorrectly, report it as an issue on the GitHub repository.
